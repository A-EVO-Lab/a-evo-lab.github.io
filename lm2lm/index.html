01 / THE RESEARCH QUESTION

Better experiments.
A learnable skill?

Research agents can write code and run experiments. The harder question is what to try next.

LM2LM asks whether experimental experience can train that judgment into a proposer’s parameters, so it suggests changes that improve a target language model—even on tasks it has not trained on.

The motivation ↗

THE COST PROBLEM

Every reward could be
a full training run.

Reinforcement learning evaluates many proposals. Executing each one makes feedback expensive to scale.

≈
THE RELIABILITY PROBLEM

A higher predicted reward
can hide a worse experiment.

As the proposer learns, it can favor changes that a world model overestimates. Old records can become misleading.

02 / THE LEARNING LOOP

Train with
predicted rewards.

Two feedback loops turn experimental experience into a learned proposal policy.

01

Ground the reward

Start with 100 real experimental records. The RWM predicts how much a proposal will improve the target model.

02

Train the proposer

DAPO optimizes Qwen3.8 27B using predicted rewards, with controls for invalid, repeated, and insufficiently diverse proposals.

03

Update experimental records

At steps 16, 40, and 64, execute selected high-rated proposals. Add their measured outcomes to the RWM’s context.

The default result is evaluated at 96 RL steps, using 200 real runs for initial records and calibration. Held-out evaluation runs are separate.

THE TAKEAWAY

Experimental experience can become
a learned research capability.

World models make feedback scalable. Real experiments keep it useful. Together, they help a language model learn which improvements are worth proposing.

What this establishes

A framework for improving proposal generation in the studied LM-development tasks. Results depend on the world model, builder, target environments, and experiment budget; they do not establish open-ended self-improvement.
